# מקומות לחופשה

מאגר מקומות החופשה של משפחת אבגיל — בארץ ובעולם.

**הדף החי:** https://yaelavgil.github.io/vacations/

## איך זה בנוי

דף סטטי ב-GitHub Pages. הדאטה לא יושב בקוד אלא ב-Realtime Database של הפרוייקט
`home-picks-47450` (אזור europe-west1), ולכן אפשר להוסיף ולערוך מקומות בלי לגעת בקוד.

| קובץ | מה יש בו |
|---|---|
| `index.html` | השלד |
| `config.js` | כתובת המסד, הרכב החבורה, הנישות, האזורים, ההחרגות |
| `app.js` | כל הלוגיקה — רשימה, מפה, כרטיס מקום, טופס |
| `style.css` | עיצוב, עברית RTL, mobile-first |
| `firebase-rules.json` | הכללים שצריך לפרסם בקונסול כדי לעבור לענף נקי |

## הנישות

1. **עם החבורה** — מתחם של 2–6 יחידות, לכל משפחה אזור משלה.
2. **רק המשפחה שלנו**.
3. **חו״ל עם ילדים**.
4. **חו״ל בלי ילדים**.

מקום יכול להשתייך ליותר מנישה אחת.

## החבורה

שבע משפחות בסך הכל. שתיים עם שני ילדים, חמש עם שלושה.
הילדים בשלושה גילאים: 12–13, 8–10, ו-5–6.

לא תמיד נוסעים כולם, ולכן כל מקום נבדק מול הרכבים של 2 עד 6 משפחות.
הבדיקה מניחה את התרחיש התובעני — שהמשפחות עם שלושה ילדים הן שנוסעות.

הדרישות הקבועות: לפחות שירותים אחד לכל משפחה, ולכל משפחה אזור משלה
עם 2–3 חדרים ומספיק מיטות.

## איפה הדאטה

```
picks/_vacations/places/<key>
```

הענף `picks` כבר פתוח לקריאה ולכתיבה בכללים הקיימים, והקידומת `_`
גורמת לקוד של `home-decisions` לדלג עליו. זה מה שמאפשר לאפליקציה לעבוד
בלי שינוי כללים.

### מעבר לענף נקי `vacations`

1. בקונסול של Firebase → Realtime Database → Rules, להוסיף את הענף שב-`firebase-rules.json` ולפרסם.
2. להעביר את הדאטה:

```bash
B=https://home-picks-47450-default-rtdb.europe-west1.firebasedatabase.app
curl -s "$B/picks/_vacations.json" > vac-backup.json
curl -s -X PUT -H 'Content-Type: application/json' -d @vac-backup.json "$B/vacations.json"
curl -s -X DELETE "$B/picks/_vacations.json"
```

3. ב-`config.js` לשנות `DB_PATH` ל-`'vacations'`, לדחוף, וזהו.
